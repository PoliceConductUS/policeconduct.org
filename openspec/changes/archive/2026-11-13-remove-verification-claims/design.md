# Approach

Remove unsupported promises rather than replace them with a new review workflow. Keep useful instructions asking for dates, locations and source links. Update both FAQ display text and JSON-LD. Existing negative disclaimers may remain but must not imply an automated alternative to manual verification. Email confirmation labels describe only mailbox confirmation; internal endpoint/status names and security checks remain unchanged.

The parent owns FAQ, donation, volunteer, news and llms copy plus project guidance. One implementer owns email/submission messages and their behavior tests. Another owns agency/personnel/civil-case forms, report/footer copy and rendered public-copy regression coverage. Use the existing worktree and PR. Finish the approved canonical-origin change, then run the full gate chain and release checks.
