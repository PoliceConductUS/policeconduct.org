# scripts

## Overview

`scripts/` holds the command-line programs that `package.json` runs to develop, build, check, release and operate PoliceConduct.org. Most files are run directly by an npm script or by another script here; a few export functions that other scripts import. Test files (`*.test.mjs`) are not described here; most sit beside the script they cover, and some cover code under `src/`. `[video.test.mjs:from "../src/lib/video.ts";]`

Citations use the form `[file:text]`. `text` is a short string that appears verbatim in `file`. `file` is relative to this directory, so `deploy.sh` means `scripts/deploy.sh` and `../package.json` means the repository manifest.

The scripts fall into these groups:

| Group                        | Files                                                                                                                                                                                                                                    |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local setup and dev server   | `bootstrap-dev.sh`, `bootstrap-all.sh`, `dev.mjs`, `run-e2e.mjs`, `openspec-status.mjs`, `update-dependencies.mjs`                                                                                                                       |
| Site build steps             | `build-release.mjs`, `validate-build-env.mjs`, `generate-icon-sprite.mjs`, `refresh-build-projections.mjs`, `generate-redirect-map.mjs`, `workspace-redirects.mjs`, `purge-built-css.mjs`, `write-release-news.mjs`, `release-files.mjs` |
| Checks on code and data      | `validate-schema-contract.mjs`, `scan-personal-data.mjs`, `verify-report-titles.mjs`, `coverage-report.mjs`                                                                                                                              |
| Checks on the built site     | `validate-no-inline-css.mjs`, `validate-critical-css.mjs`, `verify-redirect-coverage.mjs`, `audit-seo.mjs`, `audit-a11y.mjs`, `audit-a11y-checks.mjs`, `audit-route-samples.mjs`                                                         |
| Release upload and selection | `deploy.sh`, `upload-release.sh`, `promote.sh`, `load-redirects.mjs`, `manage-release.mjs`, `cleanup-preview.mjs`, `delete-noncurrent-s3-versions.sh`                                                                                    |
| Terraform guards             | `terraform-outputs.mjs`, `terraform-reviewed-apply.sh`, `require-approved-terraform-destroys.sh`, `require-terraform-account.sh`, `require-terraform-state.sh`                                                                           |
| Parameter Store secrets      | `parameter-store-secrets.sh`, `set-secret.mjs`, `audit-parameter-store.mjs`                                                                                                                                                              |
| Intake workspace             | `intake-workspace-sync.mjs`, `workspace-operator.mjs`, `workspace-demo.mjs`                                                                                                                                                              |
| External services            | `analytics-config.mjs`, `bootstrap-resend-domain.mjs`                                                                                                                                                                                    |

`generate-reports/` holds a prompt and a channel list, not code, and has no contract file.

## Interface

### Shared database helper

- Four scripts connect through `src/lib/db.js`: `refresh-build-projections.mjs`, `verify-report-titles.mjs`, `generate-redirect-map.mjs` and `coverage-report.mjs`. `write-release-news.mjs` reaches it through `src/lib/data/coverage.ts`. `[refresh-build-projections.mjs:import { withDb } from "../src/lib/db.js";]` `[verify-report-titles.mjs:import { withDb } from "../src/lib/db.js";]` `[generate-redirect-map.mjs:import { withDb } from "../src/lib/db.js";]` `[coverage-report.mjs:import { withDb } from "../src/lib/db.js";]` `[../src/lib/data/coverage.ts:import { withDb } from "../db.js";]`
- Importing that helper loads `.env` through `dotenv/config`, requires `DATABASE_URL` (it throws at import when unset), and reads the optional `DATABASE_POOL_MAX` (default 10; a value that is not an integer of 1 or more throws). `[../src/lib/db.js:import "dotenv/config";]` `[../src/lib/db.js:DATABASE_URL is required to build the site.]` `[../src/lib/db.js:DATABASE_POOL_MAX must be a positive integer]` `[../src/lib/db.js:return 10;]`
- `withDb(fn)` checks out one pooled client, runs `fn(client)` and always releases it; it opens no transaction. The pool exits when idle. `[../src/lib/db.js:export const withDb = async (fn) => {]` `[../src/lib/db.js:client.release();]` `[../src/lib/db.js:allowExitOnIdle: true,]`

### Local setup and dev server

- `bootstrap-dev.sh [--check] [--yes|-y]`: run by `npm run doctor` (with `--check`) and `npm run setup`.   - Without `--yes`, a missing installable dependency needs a terminal prompt; a non-terminal standard input exits 1. Answers `y`/`yes` install, `q`/`quit` or an empty line exit 1. `[bootstrap-dev.sh:Missing dependencies require approval. Rerun with --yes or run in an interactive terminal.]` `[bootstrap-dev.sh:y|Y|yes|YES)]` `[bootstrap-dev.sh:User quit before installing missing dependencies.]`
  - It exports `DO_NOT_TRACK=1` and `SUPABASE_TELEMETRY_DISABLED=1`, and sets `TMPDIR`, `UV_CACHE_DIR` and `UV_TOOL_DIR` to `.cache/` paths under the repository root unless already set. `[bootstrap-dev.sh:export DO_NOT_TRACK=1]` `[bootstrap-dev.sh:export SUPABASE_TELEMETRY_DISABLED=1]` `[bootstrap-dev.sh:TMPDIR="${TMPDIR:-$ROOT_DIR/.cache/tmp}"]` `[bootstrap-dev.sh:UV_CACHE_DIR="${UV_CACHE_DIR:-$ROOT_DIR/.cache/uv}"]` `[bootstrap-dev.sh:UV_TOOL_DIR="${UV_TOOL_DIR:-$ROOT_DIR/.cache/uv-tools}"]`
  - Exit 0 at the end of `main`; exit 1 on every `fail`; otherwise the status of the failing command under `set -euo pipefail`. - `bootstrap-all.sh`: no arguments, flags or environment variables; referenced only from documentation, not from an npm script. A failed pre-step exits with that step's code. Otherwise it exits with Astro's code. `[dev.mjs:Dev startup failed: ${error.message}]` `[dev.mjs:missing FORMS_API_PROXY_TARGET (expected preview forms API URL)]` `[dev.mjs:FORMS_API_PROXY_TARGET must be an absolute http(s) URL]` `[dev.mjs:missing required environment variable(s):]` `[dev.mjs:process.exit(result.code ?? 1);]` `[dev.mjs:process.exit(code ?? 0);]` When Astro ends on a signal, it exits 0 if it had forwarded `SIGINT` or `SIGTERM`, and otherwise ends itself with the same signal; a pre-step that ends on a signal does the same. `[dev.mjs:if (shuttingDown) {]` `[dev.mjs:process.kill(process.pid, signal);]` `[dev.mjs:process.kill(process.pid, result.signal);]`

### Site build steps

- `build-release.mjs`: no arguments; run by `npm run build`. `[../package.json:node scripts/build-release.mjs]`
  - It loads `.env` when present.
